# 技术方案与原理

## 1. 总体链路

```
┌──────────┐   ┌──────────────┐   ┌────────────┐   ┌───────────┐   ┌────────┐
│ 摄像头   │──▶│ YuNet 人脸框 │──▶│ 脸内角点   │──▶│ LK 光流   │──▶│ 中位数 │
│ 640×480  │   │ 每 3 帧一次  │   │ 160 个     │   │ 前后向校验│   │ dx, dy │
└──────────┘   └──────────────┘   └────────────┘   └───────────┘   └───┬────┘
                                                                       │
   ┌───────────────────────────────────────────────────────────────────┘
   ▼
┌─────────────────────────────────────────────┐
│ Mapper：与脸框中心锚定融合 + 死区 + EMA 平滑 │──▶ 头部偏移 offset (px)
└─────────────────────────────────────────────┘
        │                                   │
        ▼                                   ▼
  位置映射 pos                        速度映射 vel
  SetCursorPos(o + k·offset)         mouse_event(MOVE, v·dt)
        │                                   │
        └──────────────┬────────────────────┘
                       ▼
          停留 0.8s 且净位移 ≥ 90px  ──▶ mouse_event(LEFTDOWN/UP)
```

## 2. 人脸检测：为什么是 YuNet

| 方案 | 问题 |
|---|---|
| OpenCV `haarcascade_frontalface_default.xml` | opencv-python 5.0 已不再附带 `haarcascades` 目录 |
| dlib HOG | 需要额外编译，600×480 上 ~45 ms/帧，吃满 CPU |
| **YuNet (ONNX, 232 KB)** | `cv2.FaceDetectorYN` 内置支持，INT8 量化模型，640×480 上约 6 ms/帧 |

代价：`cv2.dnn` 的模型加载器**不接受含中文的路径**（内部按窄字符打开文件）。
本项目把模型复制到 `%TEMP%/head_mouse_yunet.onnx` 再加载：

```python
def ascii_model_path(path):
    try:
        path.encode("ascii"); return path
    except UnicodeEncodeError:
        pass
    dst = os.path.join(tempfile.gettempdir(), "head_mouse_yunet.onnx")
    ...
```

检测策略：抓不到脸时逐帧检测；抓到后每 3 帧更新一次（`FaceBox.every = 3`），
帧间靠光流维持，省下 2/3 的推理时间。实测 240/240 帧全部检出。

## 3. 特征点为什么要撒在脸框里

早期版本在整个画面（或画面中央固定 ROI）撒点，结果：**移动迟钝、且只往左上跑**。

原因有两个：

1. 画面里大量静止纹理（墙、柜子、显示器边框）也会被选成角点，
   它们的光流位移是 0，把真实的脸部运动平均掉了 —— 越大的场景越明显；
2. 少数"跑飞"的点（镜面反射、边缘、被遮挡）会产生几十像素的错误位移，
   平均值被这些离群点带偏，而偏的方向恰好是图像左上（光流搜索窗的偏好方向）。

对策：用 `FaceBox.mask()` 生成脸框内缩 10% 的二值掩膜，只在掩膜内调用
`cv2.goodFeaturesToTrack`。脸框塌缩（< 12px）时退回固定 ROI，保证不空转。

## 4. 位移估计：中位数 + 前后向校验

```python
p1, st1, _ = cv2.calcOpticalFlowPyrLK(prev, gray, pts, None, winSize=(21,21), maxLevel=3)
p0r, st2, _ = cv2.calcOpticalFlowPyrLK(gray, prev, p1, None, ...)   # 反向再算一次
good = (st1 == 1) & (st2 == 1) & (|back - pts| < 1.5)               # 前后向一致性
dx = median(p1[good].x - pts[good].x)
dy = median(p1[good].y - pts[good].y)
```

- **前后向校验**：正向跟到 `p1`，再反向跟回来，回不到原点（误差 > 1.5 px）的点直接丢。
  这是剔除遮挡 / 出界 / 匹配错误最便宜的手段。
- **中位数**：只要有超过一半的点是好的，中位数就等于真实位移；平均值不行 ——
  一个 30 px 的离群点就能把 159 个好点的结果拉偏 0.2 px，几十个离群点就直接跑飞。
- **发散重撒**：好点 < 20 个，或 75% 分位残差 > 6 px，说明点已经跟丢，立即在脸框内重撒。

## 5. 锚定融合：解决累计漂移

光流是**增量**估计，每帧的 0.1 px 偏差会一直累加，表现为"不动头，光标也在慢慢漂"。
纯光流 10.4 秒静置实测漂移 **−165 / −224 px**，必须修。

脸框中心是**绝对**参照，虽然检测有 ±2 px 抖动，但不会累加。于是把两者融合：

```
v ← v + (dx, dy)                        # 光流增量
v ← v + BETA · (anchor − v)             # 向脸框中心回拉，BETA = 0.12
offset ← v − ref                        # ref 是锁定时的 v
```

- `BETA` 太小（0.02）拽不住漂移；太大（0.5）会把真实的慢速平移当成漂移吃掉，手感发"黏"。
  0.12 对应约 8 帧（0.27 s）把偏差拉掉 63%，实测静置 8.3 秒漂移降到 **−17 / −15 px**，
  锚定残差 1.6 px（融合位置与脸框中心的距离，< 10 px 视为健康）。
- `anchor` 自身再做一次一阶低通（`ANCHOR_LR = 0.2`），压掉检测框的逐帧抖动。

## 6. 死区与平滑

```
mag = |offset|
offset_eff = offset · (1 − DEAD / mag)     # mag > DEAD，否则 0
out = (1 − SMOOTH) · out + SMOOTH · offset_eff   # SMOOTH = 0.3
```

- **死区**（`DEAD = 1.6 px`）：摄像头噪声级别的抖动直接归零，静止时鼠标纹丝不动。
  死区是"按比例削减"而不是硬截断，避免光标在死区边界上跳跃。
- **EMA**：`SMOOTH = 0.3` 相当于 ~3 帧的时间常数，既压抖动又不明显延迟。

## 7. 两种映射律

### 7.1 位置映射（默认，eViacam 风格）

```
光标 = 原点 + (offset.x · kx, offset.y · ky),  kx = 屏宽/2 / range, ky = 屏高/2 / range
```

`range` 是"头偏多少像素能横穿半个屏幕"：`1/2/3` 键对应 260 / 160 / 100 px。
2560 宽的屏上 `range = 160` → `kx = 8`，即头部 1 px ≈ 光标 8 px。
优点：位置一一对应，头停光标就停，指哪打哪；缺点：脸必须回中，长距离移动靠"大幅度"。

### 7.2 速度映射

```
m = |offset|
v = VMAX · clamp((m − VEL_DEAD) / VEL_FULL, 0, 1) ^ VEL_CURVE
光标 += v · dt
# VEL_DEAD = 7 px, VEL_FULL = 45 px, VEL_CURVE = 1.5, VMAX = 650 px/s（1/2/3 键 = 380/650/1000）
```

偏移量当作"油门"，`VEL_DEAD` 以内不动，`VEL_DEAD + VEL_FULL` 时给满速。
优点：屏幕多大都能扫到，不需要大幅度摆头；缺点：容易过冲，靠"脸回中"刹车。

**为什么有 `VEL_CURVE = 1.5`**：最初是线性 + 1500 px/s 满速，实机反馈"一动就飞到屏幕边缘"。
原因是线性映射在小区间就已经很陡：偏移 20 px 就给出 54% 满速 = 810 px/s，
而人静止时的头部抖动正好在 10~20 px 量级。加 1.5 次幂后低速段被压平：

| 头部偏移 | 线性(旧: 1500/26) | 现在(650/45, ^1.5) |
|---|---|---|
| 10 px | 231 px/s | 7 px/s |
| 20 px | 808 px/s | 101 px/s |
| 30 px | 1385 px/s | 253 px/s |
| 45 px 以上 | 1500 px/s | 650 px/s |

同样的手指级抖动，旧版能推着光标走，新版基本不动；要加速就把头多偏一点，
"油门"有了行程感，也就不会再"一下就撞边"。

> 两种都满足实验要求（"头动控制电脑，实现鼠标的移动、单击、双击"），
> 实验只规定交互目标，不规定映射律。报告里可以对比参数与主观手感。

## 8. 停留点击（dwell click）

```
still_t ≥ DWELL(0.8s)  且  cooldown ≤ 0  且  armed  且  特征点 ≥ 10  →  点击
```

`armed`（是否允许点击）用**净位移**判断，而不是累计路程：

```
dist = |光标当前位置 − 上次点击位置|
armed = dist ≥ REARM_PX (90 px)
```

为什么不是累计路程？因为手抖会让光标来回小幅移动，路程几秒内就能累加过百像素，
于是"停在原地"也能不断重新武装 → 连点。净位移在抖动时正负抵消，几乎不动。

为什么必须有这道闸？因为 `still_t` 一旦达标，人会继续停在那里，
下一帧又满足条件，就会以 `DWELL` 的节奏无限连点 —— 而真实的鼠标点击语义是
"按下—抬起"，要再点一次必须先"动一下"。所以 `armed` 本质上是把"停留"翻译成
"移动 → 停住 → 点击"的完整动作序列。界面上的 `LOCKED / ARMED` 进度条就是把这道闸可视化。

单击 / 双击：`X` 键切换，双击间隔取 `GetDoubleClickTime() / 2`（限制在 50–200 ms），
跟随系统设置，避免固定 60 ms 在慢机器上被识别成两次单击。

## 9. 光标原点为什么必须是"当前位置"

早期版本把光标映射在**屏幕中心**：`光标 = 屏幕中心 + k·offset`。带来三个问题：

1. 一按开始，光标"啪"地跳到屏幕中心，用户丢失上下文；
2. 程序窗口是小窗时，用户以为光标应该在窗口里动，实际它绕着屏幕中心动；
3. 窗口不在最前、又开着人脸控制时，光标每帧被强行拉回屏幕中心，物理鼠标也抢不回来
   —— 这是最危险的形态。

现在改成 `原点 = 按下开始时的光标位置`（`GetCursorPos`），按下前后光标**零位移**，
`O` 键可随时重取原点。屏幕多显示器时用虚拟桌面矩形 `SM_*VIRTUALSCREEN` 做边界。

## 10. 安全机制

| 机制 | 实现 | 阈值 |
|---|---|---|
| 人工接管检测 | 本帧设置光标**之前**读 `GetCursorPos`，与上次设定值比对 | > 90 px → 暂停 |
| 丢脸冻结 | `box is None and fb.enabled` → 跳过整个映射与点击流程 | 立即冻结 |
| 丢脸自动暂停 | 连续 `lost_t` 累加 | > 2.5 s → 暂停 |
| 全局急停 | `GetAsyncKeyState(VK_F8 / VK_F12)` 边沿检测 | 与焦点无关 |
| 开始/点击互锁 | 开始时 `armed = False`，需先走 90 px | 防按空格的瞬间误点 |

关键顺序：**先判断接管，再设置光标**。反过来的话，本帧刚把光标放到目标位置，
再比对自然是相等的，永远检测不到人工干预。

## 12. Win32 细节

- **DPI**：必须先 `SetProcessDpiAwareness(2)`，否则在 125%/150% 缩放下
  `GetSystemMetrics` 返回的是逻辑像素，而 `SetCursorPos` 用物理像素，光标会偏移一个缩放系数。
- **绝对移动 vs 相对移动**：位置映射用 `SetCursorPos`（绝对坐标，抗干扰）；
  速度映射用 `mouse_event(MOUSEEVENTF_MOVE, dx, dy)`（相对增量，带亚像素累加，
  否则每帧 0.4 px 的增量会被取整成 0，慢速时"走不动"）。
- **点击**：`mouse_event(LEFTDOWN/UP)` 而不是 `SendInput`，代码短且兼容性好；
  点击前不再 `SetCursorPos`，直接用当前光标位置，避免"点到别处"。
- **按键**：窗口内按键走 `cv2.waitKey`（有焦点才收得到）；
  急停键必须走 `GetAsyncKeyState`（轮询硬件状态，无焦点也有效）。

## 13. 光标可见性：叠一个分层准星窗口

系统指针最大只有 32~48 px，深色壁纸上是白箭头、白底窗口上还是白箭头，头控时很难跟住。
Windows 的"光标大小"改注册表要重新登录，所以不动系统设置，改为在指针周围叠一个窗口：

```python
CreateWindowExW(WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE,
                "STATIC", "HeadMouseHalo", WS_POPUP, ...)
UpdateLayeredWindow(hwnd, screen_dc, &dst, &size, mem_dc, &src, 0, &blend, ULW_ALPHA)
```

- `WS_EX_LAYERED`：逐像素 alpha，圆环以外全透明；
- `WS_EX_TRANSPARENT`：点击穿透，鼠标事件直接落到下面的窗口，不影响操作；
- `WS_EX_TOOLWINDOW` + `WS_EX_NOACTIVATE`：不进 Alt+Tab、永不抢焦点；
- 位图用 numpy 现算（圆环 + 四向刻度），黑-琥珀-黑三层配色，深浅背景都有对比；
- **必须预乘 alpha**（`color *= a/255`），`ULW_ALPHA` 不会帮你乘，否则边缘会发白。

位置每帧跟着 `GetCursorPos` 走；只在"正在接管光标"时 `ShowWindow`，
暂停/丢脸时立刻隐藏。个别 DirectX 独占全屏程序看不到它，属正常。
